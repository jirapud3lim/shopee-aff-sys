# การใช้ Codex Computer Use ใน Shopee Affiliate Studio

ตรวจเมื่อ 24 พฤศจิกายน 2026 จากโค้ด Studio บันทึกการทดสอบ และประวัติการเรียกเครื่องมือของ Codex ในงาน GAMBOL, DoCoMall และ JUDYDOLL ที่เปิดอ่านได้

**ข้อกำหนด production** ห้ามนำ Codex Computer Use ไป deploy หรือเรียกใช้จากเว็บ API worker งานตามเวลา หรือบริการภายนอกที่รับงานแทน production ต้องทำงานได้โดยไม่มี Codex, Safari Capture หรือ browser automation เป็น dependency เส้นทางที่ต้องทำในพอร์ทัลให้ผู้ใช้เปิดและดำเนินการเอง แล้วนำผลกลับเข้า Studio

| ขั้นใน Pipeline | ฟีเจอร์ของ Studio | การใช้ Codex Computer Use ที่ตรวจพบ | วิธีทดแทนใน production |
|---|---|---|---|
| 1. ค้นหาและจัดอันดับสินค้า | Google Trends ไทย จับคู่คลังสินค้า กรองข้อเสนอตามยอดขายและค่าคอม | **ใช้จริงบางส่วน** ค้นข้อเสนอและอ่านยอดขายกับค่าคอมใน Shopee Affiliate รอบ GAMBOL การจัดอันดับทำใน Studio | ใช้ RSS และระบบจัดอันดับเดิม รับข้อมูลจากรายการที่บันทึกไว้หรือเพิ่มเอง ต่อ Shopee Affiliate Open API เมื่อยืนยันสิทธิ์ [PRD-02](../backlog/PRODUCTION_NO_COMPUTER_USE.md#prd-02) |
| 2. บันทึกและยืนยันสินค้า | เก็บรายการสินค้าและหลักฐานสิทธิ์ใช้ภาพ ตรวจ Shop ID, Item ID และตัวเลือก | **ใช้จริงบางส่วน** เปิดรายการและตรวจตัวเลือก เช่น DoCoMall A‑100cm สีขาว การเก็บข้อมูลทำใน Studio | รับ URL และภาพตัวเลือกจริง ตรวจ ID ฝั่ง server และให้ผู้ใช้ยืนยัน variant ในหน้ารายการ [PRD-02](../backlog/PRODUCTION_NO_COMPUTER_USE.md#prd-02) |
| 3. สร้างลิงก์ Affiliate | เก็บลิงก์แยกช่องทางพร้อม Sub ID | **ใช้จริงบางส่วน** สร้างลิงก์จริงใน Shopee รอบ GAMBOL ระบบกรอกฟอร์มและรับผลอัตโนมัติใน Studio ใช้ Safari Capture | เตรียม URL และ Sub ID ใน Studio ให้ผู้ใช้สร้างใน Shopee แล้ววางผลกลับ เพิ่ม API เมื่อได้รับสิทธิ์ [PRD-03](../backlog/PRODUCTION_NO_COMPUTER_USE.md#prd-03) |
| 4. ทำ Storyboard | เก็บภาพอ้างอิง พรอมป์ ลำดับช็อต และการอนุมัติตามเวอร์ชัน | **ใช้จริง** เปิด Flow แนบภาพ ส่งพรอมป์ สร้างหรือแก้ภาพนิ่ง ผู้ใช้เป็นผู้อนุมัติ | ส่งออกพรอมป์และชุดภาพให้ผู้ใช้ทำใน Flow แล้วนำเข้าภาพแยกช็อต ทดสอบ Gemini Image API สำหรับภาพนิ่ง [PRD-04](../backlog/PRODUCTION_NO_COMPUTER_USE.md#prd-04) |
| 5. สร้างและประกอบวิดีโอ | ส่งต่อช็อตอนุมัติไป Flow แล้วประกอบด้วย FFmpeg | **ใช้จริงบางส่วน** ตั้งค่า สั่งสร้าง และดาวน์โหลดช็อตใน Flow ส่วนการประกอบใช้ FFmpeg | ผู้ใช้สร้างใน Flow ด้วย Veo 3.1 Lite และเสียง Callirrhoe แล้วอัปโหลดตามช็อต ทดสอบ Veo และ TTS ผ่าน API แยกกัน [PRD-05](../backlog/PRODUCTION_NO_COMPUTER_USE.md#prd-05) · [PRD-06](../backlog/PRODUCTION_NO_COMPUTER_USE.md#prd-06) |
| 6. ตรวจและส่งออก MP4 | ตรวจสัดส่วน เปิดพรีวิว และยืนยันเวอร์ชันก่อนเตรียมโพสต์ | **ใช้จริงบางส่วน** ยืนยันได้ว่าตรวจคลิปต้นทางใน Flow ยังยืนยันการใช้ Computer Use ตรวจ MP4 สุดท้ายทั้งไฟล์ไม่ได้ การส่งออกและตรวจสเปกใช้ FFmpeg/FFprobe | ตรวจสเปกอัตโนมัติ และให้ผู้ตรวจดูและฟัง MP4 จนจบก่อนอนุมัติ [PRD-07](../backlog/PRODUCTION_NO_COMPUTER_USE.md#prd-07) |
| 7. เตรียมโพสต์ จัดคิว และเผยแพร่ | เตรียมไฟล์ แคปชัน และการเปิดเผย จัดคิวและใช้ Meta API หรือส่งต่อหน้าเว็บ | **ไม่ใช้ในคิวและ Meta API** มีบันทึกอัปโหลดทดสอบใน Safari แต่ประวัติที่ตรวจยังยืนยันเครื่องมือที่ใช้กับรอบ Facebook และ TikTok นั้นไม่ได้ | Meta API เมื่อใช้ตัวควบคุมที่จำเป็นได้ครบ หรือให้ผู้ใช้ทำบน Facebook/TikTok พัฒนา TikTok Inbox Upload เมื่อได้สิทธิ์ [PRD-08](../backlog/PRODUCTION_NO_COMPUTER_USE.md#prd-08) · [PRD-09](../backlog/PRODUCTION_NO_COMPUTER_USE.md#prd-09) |
| 8. วัดผล Affiliate | นำเข้า CSV จับคู่ช่องทางและ Sub ID แล้วสรุปคลิก ออเดอร์ และค่าคอม | **ไม่ใช้ในขั้นประมวลผล** ยังไม่พบหลักฐานการเรียกเครื่องมือตอนดาวน์โหลดรายงานจาก Shopee | ให้ผู้ใช้ส่งออก CSV จากพอร์ทัล ใช้ตัวนำเข้าเดิมและพิจารณา Reporting API หลังเทียบยอด [PRD-10](../backlog/PRODUCTION_NO_COMPUTER_USE.md#prd-10) |

เกณฑ์ผลลัพธ์ตรงกันคือสินค้าและช่องทางเดิม ชุดช็อตและเวอร์ชันที่อนุมัติ คลิปและเสียงที่ผ่านการตรวจ โพสต์และลิงก์ที่ยืนยันได้ และรายงานที่เทียบยอดได้ สื่อที่สร้างใหม่ต้องผ่านเกณฑ์ภาพและเสียงเดียวกัน ส่วนไฟล์เดิมที่ส่งผ่านหลายขั้นให้ตรวจด้วย hash เวลาที่ใช้และจำนวนขั้นตอนของผู้ใช้บันทึกแยกจากคุณภาพผลลัพธ์
